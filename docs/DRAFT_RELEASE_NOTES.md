## Summary

Unofficial experimental patch for the Docker source-build failure described in [SamNet-dev/MTProxyMax issue #162](https://github.com/SamNet-dev/MTProxyMax/issues/162).

A Dockerfile generated by MTProxyMax attempted a Bash-specific substring expansion inside a POSIX-shell `RUN` command. The patch uses POSIX-compatible `printf` to compare the short pinned Telemt commit.

## Changes

- Replace Bash-specific substring in both the generated Dockerfile and GitHub image-build workflow.
- Prevent the fork's `self_update()` from overwriting a local forked manager with the original upstream manager by default.
- Abort the update path after failed image builds.
- Retain previous Docker images and previously running container during protected engine upgrades, with attempted restoration on failure.
- Preserve previous Telemt version marker when restart fails.
- Snapshot `config.toml` and restore it atomically before restarting the previous container if the replacement fails.
- Require a pinned 40-hex commit and SHA256 for fork installs and explicit fork-manager script updates; back up installed manager before overwriting it.
- Add static checks, multi-distribution unit tests, offline Telemt smoke, real Docker rollback integration, and isolated Telemt + HAProxy regression checks.

## Verification performed

The original CI, smoke, real Docker rollback, and synthetic HAProxy full-stack checks passed on baseline commit `496ae9f19e78f8e6095cbd14ff23c1bd9c2adaed`. Subsequent integration runs also demonstrated restoration of a deliberately modified `config.toml`. The current candidate must pass all final CI checks before release review; see [the release readiness audit](RELEASE_READINESS_AUDIT.md) for evidence and limitations.

**Not tested:** successful client traffic via Telegram, behavior with the actual production HAProxy setup, complete rollback of all files and auxiliary instances, real VPS upgrade. The synthetic full-stack exercises a replacement launch function rather than the production `run_proxy_container()` end to end.

## Installation and upgrade

The fork's `install.sh` is now restricted to an explicitly supplied reviewed 40-hex `MTPROXYMAX_SOURCE_COMMIT` and matching 64-hex `MTPROXYMAX_SOURCE_SHA256`. It refuses to install from a moving branch or with no trusted checksum. The legacy README quick-start is an **upstream installation command**, not a fork installation command; a warning has been placed above it.

`self_update()` can explicitly fetch a reviewed fork revision with `MTPROXYMAX_FORK_UPDATE_COMMIT` and `MTPROXYMAX_FORK_UPDATE_SHA256`, and requires an existing-manager backup before script replacement. By default, upstream self-update attempts are blocked from replacing the fork.

**No immutable public release revision and its checksum have been designated.** Thus no copy/paste public installation command is provided yet; usage remains restricted to controlled development testing.
