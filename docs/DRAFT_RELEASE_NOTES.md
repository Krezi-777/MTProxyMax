## Summary

Unofficial experimental patch for the Docker source-build failure described in [SamNet-dev/MTProxyMax issue #162](https://github.com/SamNet-dev/MTProxyMax/issues/162).

A Dockerfile generated by MTProxyMax attempted a Bash-specific substring expansion inside a POSIX-shell `RUN` command. The patch uses POSIX-compatible `printf` to compare the short pinned Telemt commit.

## Changes

- Replace Bash-specific substring in both the generated Dockerfile and GitHub image-build workflow.
- Prevent the fork's `self_update()` from overwriting a local forked manager with the original upstream manager by default.
- Abort the update path after failed image builds.
- Retain previous Docker images and previously running container during protected engine upgrades, with attempted restoration on failure.
- Preserve previous Telemt version marker when restart fails.
- Add static checks, multi-distribution unit tests, offline Telemt smoke, real Docker rollback integration, and isolated Telemt + HAProxy regression checks.

## Verification performed

The CI, smoke test, real Docker rollback, and synthetic HAProxy full-stack checks passed on development commit `496ae9f19e78f8e6095cbd14ff23c1bd9c2adaed`. See [the release readiness audit](RELEASE_READINESS_AUDIT.md) for individual evidence links and limitations.

**Not tested:** successful client traffic via Telegram, behavior with the actual production HAProxy setup, complete file/configuration rollback, auxiliary-instance recovery, real VPS upgrade.

## Installation and upgrade

**Intentionally omitted until fixed and verified.** Do not use the repository's current `install.sh` as an installer for the fork: it retrieves the original upstream manager from `SamNet-dev/MTProxyMax/main`. Do not run the original README's upstream quick-start and expect this patched branch.

A future stable release must provide a pin to a reviewed commit or immutable tagged revision, verification of the manager source, and a clearly documented upgrade/rollback procedure.
